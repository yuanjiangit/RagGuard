# Judge 成本估算

> 用户最担心的"评估一次花多少钱"，用公式和实测口径回答。缓存（M4 落地）是最大的省钱杠杆。

## 1. 调用次数模型

一次全量评估（`N` 道测试题，四个指标全开）：

| 指标 | judge 调用 | 嵌入调用 | 备注 |
|---|---|---|---|
| faithfulness | 1 次/题 | — | 拆解+判定合并为一次结构化调用 |
| answer relevance | 1 次/题 | (1+N̂) 次/题 | N̂=反向问题数，默认 3；嵌入可用本地模型归零 |
| context recall | 1 次/题 | — | 依赖 expectedAnswer；空则跳过 |
| context precision | 1 次/题 | — | k 条上下文合并一次判定 |

**合计 ≈ 4 次 judge 调用/题 + 4 次嵌入/题**。所有调用都带短路：空答案、空上下文、缺 expectedAnswer 的题目**零调用**。

解析失败重试上限 2 次，只影响异常样本。

## 2. Token 量级（粗估）

以 `gpt-4o-mini` 价格口径（输入 $0.15/M、输出 $0.60/M token，2025 价格，发布时请以当前价为准）：

- 每次判定输入 ≈ 0.5~2K token（含 system prompt + 上下文），输出 ≈ 0.2~0.5K token
- **每题约 6~10K token，20 题全量约 15~25 万 token ≈ $0.05~0.10**
- 开缓存后：测试集未变的重跑 ≈ **$0**（缓存命中零调用）

## 3. 三个省钱杠杆（按收益排序）

1. **判定缓存**（`ragguard.judge-cache-enabled: true`）：按 (模型, prompt 版本, 输入 hash) 缓存 raw 判定文本；日常迭代中通常 80%+ 的题目不变 → 绝大多数调用归零。缓存文件不要提交进 git。
2. **便宜模型当 judge**：judge 与被测模型解耦，`gpt-4o-mini` 级别足够稳定（先跑稳定性测试验证你自己数据集上的方差）。
3. **指标子集**：日常门禁只盯 faithfulness + context recall，PR 级成本立减一半；全量四指标留给夜间/发布前。

## 4. 稳定性 vs 成本的取舍

`JudgeStabilityTest`（20 次全量）是**一次性**成本（≈ 全量评估 × 20，只跑一次留档），换 README 里公开的方差数据——"LLM 打分靠谱吗"的答案。

可选多数投票（3 次判定取众数）成本 ×3，默认关闭，仅对高争议题目建议手动复核而非全局开启。
